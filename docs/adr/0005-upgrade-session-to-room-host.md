# 会话可就地升级为 Room Host

## Status
accepted

## Context
用户往往已经在与本地 agent 对话时才提出"叫上另一台设备一起"的需求。若必须新建会话或切换设备，上下文要搬运、体验割裂。DSH 插件已具备向已有会话日志追加自定义事件并用投影渲染的能力（Agent Team 是现成先例），因此房间状态可以附着在一个已有会话上。

## Decision
当前会话可被显式升级为 Room Host：向会话日志追加 `room/*` 事件并挂载 room 投影，保留原有对话上下文。此后以**统一成员接口**添加任意成员（B、C、D……）：每台设备对应一个 Participant，Host 只是带 `host` 角色的成员，添加/退出/发言走同一套调用，界面上的名称区别不改变语义。规则：
- 一个会话最多承担一个 Room 的 `host` 角色；
- 已是 Participant 的会话不能升级为 Host（另开会话）；
- fork 一个 Host 会话时，子会话不继承 Host 角色或成员关系；
- Host 会话关闭/归档 → 房间进入只读或结束，Participant 收到通知；
- 升级与添加成员都是显式动作，不能隐式发生。

## Considered Options
- 总是新建 Room 会话——上下文需搬运，体验割裂，否决。
- 由目标设备建房、本机以远端身份加入——当前会话不升级，仍有切换感，否决。

## Consequences
房间生命周期绑定 Host 会话，fork/关闭/归档需要额外规则；成员模型保持统一，房间规模与设备命名不影响实现语义。
