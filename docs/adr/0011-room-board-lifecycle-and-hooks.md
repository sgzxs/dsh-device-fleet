# Room Board 与房间同生命周期，更新由钩子驱动

## Status
accepted

## Context
Room Board 要解决"被唤醒的 agent 不必读全量聊天记录就能进入状态"以及"多 agent 串行/并行推进同一件事时状态不丢"。若沿用本机全局任务库，生命周期与房间不一致；若每次变化广播给所有成员，又会造成重复唤醒与 token 浪费。

## Decision
- **Room Board 与 Room 同生命周期**：随房间创建/归档；Host 权威、参与设备只读镜像（扩展 `dsh-global-task-list` 的 `task_ui`，加 `roomId`）。
- **Room 中至少存在一个 agent**（Host 的 agent 即成员）；每个成员的执行单元是 **Task Block**。
- **任务按块分配**：
  - 串行块：上一块完成后，其负责人更新 Room Board，Host 将下一块标记为 ready 并向下一块的负责人发一条点名消息（唤醒它接手）；
  - 并行块：各成员只更新自己块的状态，不阻塞/不改变其他块；下一阶段开始时读取当前 Board 即可了解全貌。
- **更新由钩子驱动**：
  - 成员被唤醒领取一块任务时，任务简报里包含该块 + 相关 Board 切片，并提醒开始执行时标记状态；
  - 成员结束一轮时，Host 检查其负责块的 Board 状态；若明显未更新，发一条（最多一次）提醒消息；
  - 任何成员开始新块前自行读取 Board（拉取），不要求全量推送。
- 其他成员不需要在每次变化时被唤醒；只在被点名（含"下一块 ready"）时唤醒。

## Considered Options
- 沿用全局个人任务库、不区分房间——生命周期不一致，个人任务与房间任务互相污染，否决。
- 每次 Board 变化广播唤醒所有成员——token 浪费、互相打断，否决。
- 完全依赖模型自觉更新——task-list 的经验表明会漏更新，否决。

## Consequences
需要在 turn 边界做 Board 一致性检查与有限提醒；串行交接会产生点名唤醒消息；Board 需要版本号/CAS 防止覆盖；参与设备的镜像是只读的，写入统一回 Host。
