# 直调与协作分成两条通道

## Status
accepted

## Context
把"只是调用对方一个工具"塞进 Room 或 Participant 会话，会让一次纯工具调用带上对话上下文、会话生命周期与模型唤醒的包袱；反过来，把"多 agent 协作"做成一次性工具调用又丢掉了共同历史与任务状态。两者需要不同的生命周期与上下文预算。

## Decision
分成两条通道：
- **Direct Call（直调）**：A 的 agent 直接调用目标设备上的 tool 并取回结果；不创建 Room/Participant、不读取目标设备对话上下文；目标设备插件按"设备 × 工具"配置决定免审批 / 需本机审批 / 拒绝。
- **Room（协作）**：只有需要目标设备的 agent 参与时才创建 Participant，给任务简报 + 定向消息，共享房间历史与任务板。

直调遇到有状态工具（执行代码、写文件）时，目标设备使用插件管理的隐藏 **Execution Slot** 提供 cwd、沙箱与审批路由；它不跑模型、不进 Room、不保存对话历史。

## Considered Options
- 所有直调都走 Room 的 Participant 会话——上下文与生命周期过重，否决。
- 直调只允许无状态工具（跑代码必须升级为 agent 任务）——限制过强，否决。
- 所有直调统一走执行槽——纯读也带上下文，偏重，否决。

## Consequences
直调与协作可以独立演进，token 与上下文成本可控；直调的执行安全由目标设备插件的工具策略负责；执行槽对用户不可见，但会出现在设备内部审计里。
