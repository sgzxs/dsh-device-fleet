# Room 作为去中心化的本地副本容器

**Status**: accepted

原来的 Room 由一台 Host 持有唯一权威历史，其他设备只是只读 Mirror；这种模型下 Host 离线、迁移或多 agent 协作都会受单点限制。我们决定把 Room 改成每个参与设备各持一份可写的 Room Replica：事件日志追加、快照压缩、按需同步，成员表/任务/策略通过 CRDT 合并；创建者只是可选的 Coordinator，不再拥有写入权威。这样 Room 可以脱离 Host 存续，同一设备上的多个 session 共享同一副本，User 可见全部事件，而 agent 只拿到点名交接与任务上下文。

## Considered Options

- **Host 唯一权威 + 离线排队**：实现简单、排序确定，但 Host 缺席时无法真正继续协作，与“Room 作为容器长期存在”的目标冲突。
- **完整区块链共识**：每个事件要求多数设备确认，过于沉重，牺牲离线可用性和延迟，收益不足。
- **只同步最新快照（LWW）**：最简单，但会丢失并发消息与历史，无法满足审计与可重放。

## Consequences

- Room 状态是最终一致的，短时间内不同设备可能看到不同内容；UI 需要显示同步/pending 状态。
- 需要事件日志、快照、向量时钟、成员/任务 CRDT、Room Invite/key 轮换、签名校验与迁移工具。
- 安全模型从“Host 授权”变为“设备签名事件 + Room key + 成员 Policy”；被移除设备无法阻止其保留已同步的明文历史。
- 旧的 Host/Mirror 代码、术语和测试需要迁移或废弃；旧 Room 需要一次性导入事件日志。
