# Room 消息必须点名，且每个成员设备都能发言

## Status
accepted

## Context
用户会在不同设备之间切换使用（可能这次对 A 说，下次对 B 说），因此"只有发起者/Host 能发言、其他人只能被动接受"不成立；同时，若每条消息都唤醒所有 agent，会造成 token 浪费、互相打断与重复工作。

## Decision
- **每条 Room 消息都带显式收件人**（成员 id 集合；`*` 表示广播，但需显式授权/确认，不是默认行为）。只有被点名的成员被唤醒；未点名成员不跑模型，但仍共享房间权威日志。
- **Room 视图在所有成员设备上可用**：Host 广播权威日志，成员设备的 UI 订阅展示；从任何设备发言使用同一套接口，从而支持用户"人在这台、下一句换那台"的无感切换。
- 发言者身份分为两类并都进入权威日志：**用户**（人在某台成员设备上直接发言）与 **agent**（成员设备上的 agent 发言）。
- Host 的 agent 天然是成员之一，但不再垄断发言；Host 的会话只负责托管日志与排序，未点名时不会因日志追加而被唤醒。

## Consequences
成员设备需要房间视图与收发通道；Host 需要广播与排序；"点名"成为协议字段而不是 UI 装饰；未点名成员保持静默。
