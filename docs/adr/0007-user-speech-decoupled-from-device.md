# 用户发言与设备解耦，消息 = 内容 + 发言者 + 点名

## Status
accepted

## Context
用户会在 A、B 等设备之间切换发言。如果把"用户"绑定到具体设备，同一人会被拆成多个发言者/接收者，通知、审计与房间状态都会出现无意义的重复；而一条用户消息本质上是无状态的指令或信息，真正决定它被谁处理的是收件人。

## Decision
- 用户是跨设备的**单一发言者身份**；设备只是消息的传输来源，仅作审计元数据，不进入房间状态与路由语义。
- 一条 Room 消息由三部分组成：**内容**、**发言者**（`user` 或某个 agent 成员）、**点名**（收件成员集合）。消息本身不携带设备状态。
- 用户从任何成员设备直接发言，都以同一 `user` 身份进入权威日志，并直接唤醒被点名的 agent；本机 agent 不参与转发、不消耗本机 token。
- 用户也可点名本机 agent，让它以该设备上的 agent 成员身份参与。

## Considered Options
- 每个设备一个"用户身份"——同一人被拆分，通知/审计/状态重复，否决。
- 用户消息一律由本机 agent 代理转发——每次多一次模型调用，也无法精准点名，否决。
- 只有 Host 设备能发言——违背"任意设备无感交流"，否决。

## Consequences
房间可以只维护一份人工发言者视角；同一用户的房间视图在各设备一致。未来若支持多人房间，需要引入真正的多用户身份，一期不做。
