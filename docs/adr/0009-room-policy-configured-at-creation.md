# Room 由显式命令创建，并携带可配置的 Room Policy

## Status
accepted

## Context
Room 只在用户显式命令下创建（升级当前会话或新建房间），因此创建之前用户可以在插件设置里预设"房间类型与权限"；不同协作场景需要不同规则（私密房间只让 Host 拉人，团队房间允许任意成员邀请并自动通过）。把这些行为硬编码会逼用户改代码。

## Decision
- 插件提供**默认 Room Policy 与命名预设（Room Type）**，例如私密、团队、只读；
- 创建房间（升级当前会话或新建）时，把所选类型解析成一份**策略快照**，写进房间创建事件并广播给成员；
- 邀请权、加入方式（自动/需确认）、成员上限、任务板写权限等协作规则由该策略决定，而不是硬编码；
- 默认取插件配置，创建时可覆盖；Host 可在创建后修改协作类策略（记录并广播），但不追溯驱逐既有成员；
- **边界**：Room Policy 只管协作规则；资源访问（直调某设备的工具、读写其文件）仍由各设备的 Tool Policy 决定，两者不重叠。

## Considered Options
- 硬编码"仅 Host 邀请 + 自动加入"——无法按场景配置，否决。
- 全局唯一策略——无法同时支持私密房间与团队房间，否决。

## Consequences
房间事件需要持久化策略快照；房间 UI 要显示当前策略；策略修改要审计；实现上必须明确 Room Policy 与设备 Tool Policy 的分界，避免"房间允许"被误当成"资源允许"。
