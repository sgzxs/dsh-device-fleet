# 直调授权由资源所有者设备决定

## Status
accepted

## Context
直调（Direct Call）让 A 的 agent 使用 B 的工具。B 的文件、机器与风险都属于 B，A 不能给自己授权；但逐次弹窗会让一个多步任务反复打断。

## Decision
直调的工具策略由**目标设备（资源所有者）**的插件按"设备 × 工具"配置，默认分级：
- 只读工具：免审批，受目标设备配置的目录根与白名单限制；
- 执行类（bash/pwsh/terminal/子进程）与写文件：需目标设备本机确认；
- 危险类（plugin_manager、schedule_*、CUA、交互式终端等）：默认拒绝，须在目标设备设备页显式开启。

审批在目标设备的插件界面/队列中显示来源设备、agent 会话、工具名、参数预览、cwd 与超时；超时 fail-closed；允许"本次任务内记住（TTL）"。A 侧不能代 B 授权，审批结果记入目标设备审计。

## Considered Options
- 审批转发到 A 的用户——把 B 的资源授权交给 A 侧的人，违背资源所有者原则，否决。
- 每台设备一个总开关——粒度太粗，表达不了"读可以、跑代码要问"，否决。
- 入网即全授权——最省事也最危险，否决。

## Consequences
"读"与"执行/写"需要分开配置；直调的可用性依赖目标设备有人/有策略回应审批；TTL 授权会短暂扩大目标设备的暴露面，需要审计与撤销。
