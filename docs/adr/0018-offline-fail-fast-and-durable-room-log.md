# 离线成员：直调/委派快速失败，房间日志承担持久补发

## Status
accepted

## Context
设备会离线。把工具执行或委派任务排队到目标恢复后再执行，会让过期指令在数小时后突然生效，语义与安全都不可控；而 Room 又需要让离线成员回归后能接上协作现场。

## Decision
- **直调与委派立即失败**：目标设备离线时返回明确错误（`offline`，附最后在线时间），不排队；由本地 agent 决定重试、换设备、或改为发 Room 消息/任务。
- **Room 消息持久化**：Host 权威日志就是离线消息的归宿；离线成员不被唤醒。成员回归后按"自上次已读"补一份**摘要 + 被点名的消息**，**最多唤醒一次**，不逐条重放。
- **离线成员的 Task Block** 保留在 Room Board 上，Host 不代其执行；成员回归后按 Board 切片继续。
- 需要"离线也能跑"的场景，后续再引入显式 outbox（v1 不做）。

## Considered Options
- 全部排队（直调短暂排队、委派持久 outbox、Room 逐条补发）——过期指令风险高、语义复杂，否决。
- 混合排队——多一套 outbox 与过期策略，v1 不必要，否决。
- 按房间/设备可配置——灵活性留到以后，v1 用统一语义，否决。

## Consequences
没有"离线执行保证"；Room 可能积累未读（需要每成员已读游标与摘要生成）；离线成员的 Block 可能长期停留，需要 Room UI 标注 stale/offline。

## 追记（1.18.0）

- 普通直调/委派仍保持 fail-fast；新增**显式 opt-in** 的持久化 outbox：`fleet_queue_call` / `fleet_queue_delegate`。
- 这不算推翻本决策：默认语义仍不排队，只有调用方明确要求“稍后执行”时才落盘并在重连/重试时执行。
