# Room 可见性：用户看完整对话，agent 只看自己的与点名给它的

## Status
accepted

## Context
用户需要一份完整、可回看的房间对话；但把房间全部历史注入每个 agent 的上下文，会浪费 token、分散注意力，也会让 agent 看到与自己无关的工作细节。点名机制（ADR-0006）已经提供了天然的可见性边界。

## Decision
- **Room 日志是完整、append-only 的**：所有消息（用户与 agent、含 agent 之间的消息）、成员/策略变更、Board 审计指针都写入 Host 会话日志；任意成员设备上的 Room UI 都渲染**完整对话**，用户是单一身份。
- **每个 agent 的上下文只包含**：
  1. 它自己的会话历史（自己的动作、工具调用与结果、自己的回合）；
  2. 点名发给它的消息（来自用户或其他 agent）；
  3. 它自己发出的消息；
  4. 与它负责的 Task Block 相关的 Board 切片。
  未被点名给它的消息、其他 agent 的工作与私有上下文，**不会进入它的 prompt**。
- **Host 的 agent 同样遵守**：Host 会话日志里的 `room/*` 事件是 log-only；只有点名给它的消息才以带发送者归属的 user 消息注入它的对话。
- **唤醒简报** = 任务块 + 点名消息 + Board 切片 + 版本，不是房间历史。
- 存储采用双轨：消息/成员/策略/生命周期在会话日志，Room Board 任务在扩展后的 `task_ui` 域（权限 ADR-0008）；两者通过 room 投影组合。

## Considered Options
- 所有房间消息都注入所有 agent——token 与注意力浪费、无关信息干扰，否决。
- 用户只能看到与自己相关的消息——违背"完整对话"诉求，否决。

## Consequences
需要按成员维护"已读游标"与消息路由；Room UI 需要完整历史视图与成员过滤视图；agent 之间的消息对用户可见（可审计）；agent 的私有工作轨迹留在各自设备的会话里，默认不并入房间记录（避免噪声与跨设备内部信息泄露）。
